# Разработка и проверки

Команды выполняются из корня проекта. Быстрый запуск и переменные окружения описаны в [README](../README.md).

## Окружение

- Node.js 22.13+ и npm; версия CI указана в `.nvmrc`.
- Chromium для Playwright: `npx playwright install chromium`.
- Docker с Compose для проверки production.
- OpenSSL для генерации временного сертификата smoke-теста. В Linux он должен быть в PATH; в Windows используется стандартный путь Git for Windows. Другой путь можно задать в `OPENSSL_PATH`.

## Команды

```bash
npm ci
npm run check
npm run test:coverage
npm run test:e2e
npm run test:production
```

`check` последовательно проверяет Prettier, ESLint, TypeScript, Vitest и сборку. E2E и Docker smoke запускаются отдельно. `npm run format` изменяет форматирование; `format:check` только проверяет.

## Что покрывают тесты

### Unit и интеграционные: Vitest, Testing Library, MSW

- Разбор допустимых и ошибочных query-параметров, включая крайние числовые значения.
- Контракт Guardian: параметры запроса, список, детали, отсутствующие поля, невалидные данные и безопасная обработка анонса.
- Начальная загрузка, ошибка, повтор запроса, пустая и недоступная страница.
- Переходы между страницами, изменение лимита со сбросом страницы, прямые адреса и возврат из статьи.
- Сохранение контекста старых карточек при загрузке следующей страницы.
- Сохранение кешированного списка и статьи после ошибки фонового обновления.
- Отсутствующая новость, ошибки детали, отмена запроса и правила повторных запросов.

Исходники находятся в `src/**/*.test.ts(x)`, общие обработчики — в `src/test/mocks`. MSW блокирует необработанные запросы, поэтому тесты не зависят от доступности Guardian.

### Браузерные: Playwright

`e2e/app.spec.ts` проверяет собранное приложение в desktop- и mobile-конфигурациях Chromium: каталог, пагинацию, смену лимита, переход и прямое открытие статьи, историю браузера, восстановление после ошибок, клавиатурное управление и отсутствие горизонтального переполнения. Ответы API и изображения подменяются внутри браузерных тестов.

Если CDN Playwright недоступен, для локальной диагностики можно использовать установленный Chromium-совместимый браузер, задав абсолютный путь в `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. В CI браузер устанавливается штатно. Запуск с другим браузерным бинарником не равнозначен проверке на закреплённом Playwright Chromium.

### Production: Docker и настоящий Nginx

`scripts/smoke-production.mjs` собирает образ и запускает изолированный HTTPS upstream под адресом Guardian внутри временной Docker-сети. Проверяются:

- отказ запуска без ключа и с недопустимым значением;
- отказ TLS-соединения с недоверенным сертификатом и успешный запрос с тестовым доверенным CA;
- передача только серверного ключа, фильтрация параметров, исключение клиентских Authorization/Cookie;
- список и деталь через настоящий proxy, общий интервал запросов и `429` при переполнении очереди;
- health endpoint, SPA fallback, защитные заголовки и политика кеширования HTML/ассетов;
- отсутствие контрольного значения ключа в HTML, JS и CSS именно итогового образа; отсутствие файлов также считается ошибкой.

OpenSSL создаёт сертификат во временном каталоге. Системное хранилище доверия не меняется: сертификат монтируется только в тестовый контейнер. Ресурсы удаляются в `finally`. Для проверки уже собранного образа задайте `IMAGE_TAG`; без него скрипт сам выполняет `docker build`.

Эти проверки не подтверждают работоспособность выданного вам реального ключа. Её нужно проверить отдельным ручным запуском с Guardian.

## CI

На каждом push, pull request в `master` и `workflow_dispatch` запускаются три блокирующих job:

1. Форматирование, ESLint, TypeScript и Vitest с покрытием.
2. Playwright на production-сборке.
3. Аудит runtime-зависимостей и Docker production smoke.

`PR gate` агрегирует результаты. Отчёты покрытия и Playwright хранятся семь дней. Защита ветки и required checks настраиваются в GitHub отдельно; автоматической публикации приложения нет.

## Ручная проверка перед публикацией

Проверьте реальные новости с действующим ключом, прямые URL списка и статьи, смену лимита и возврат, клавиатуру и читаемость на узком экране. В Docker выполните `docker compose ps` и дождитесь `healthy`. Такой прогон дополняет автоматические тесты, использующие подменённый API.

## Диагностика

- **Playwright не находит браузер:** выполните `npx playwright install chromium`; при медленном CDN можно увеличить `PLAYWRIGHT_DOWNLOAD_CONNECTION_TIMEOUT`.
- **401/403 от Guardian:** проверьте ключ и права доступа, перезапустите Vite или пересоздайте контейнер.
- **429:** подождите; это ограничение очереди proxy или квоты внешнего API.
- **Docker не запускается:** ключ обязателен и должен содержать только буквы, цифры, дефисы и подчёркивания.
- **Ошибка TLS smoke:** проверьте OpenSSL, Docker и доступность скачивания базовых образов. Реальный Guardian API для smoke не нужен.
- **Прямой маршрут возвращает 404:** используйте конфигурацию Nginx из проекта с SPA fallback.
