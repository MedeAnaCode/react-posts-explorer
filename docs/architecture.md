# Архитектура

Приложение — SPA на React 19 и TypeScript с внешним Guardian Content API. Собственных базы данных, авторизации и серверной бизнес-логики нет.

## Границы модулей

- `app` — QueryClient, глобальные провайдеры и маршруты.
- `pages` — композиция списка, детали и пользовательских состояний.
- `entities/post` — API-функции, Zod-схемы и карточка новости.
- `features/posts-pagination` — чтение и нормализация query-параметров, выбор лимита и кнопки.
- `shared` — HTTP-клиент, политика ошибок и общие UI-состояния.

Страницы используют публичные экспорты нижних модулей; `shared` не зависит от бизнес-сущностей. Дополнительного глобального store нет: URL хранит навигацию, TanStack Query хранит серверные данные.

## Маршруты и состояние

| Маршрут                          | Назначение                                       |
| -------------------------------- | ------------------------------------------------ |
| `/`                              | Перенаправляет на `/posts?page=1&limit=10`.      |
| `/posts?page=2&limit=20`         | Список с воспроизводимыми параметрами пагинации. |
| `/posts/:postId?page=2&limit=20` | Статья и параметры возврата к списку.            |
| Любой неизвестный путь           | Страница 404.                                    |

Guardian ID содержит слеши: карточка кодирует весь ID в один сегмент маршрута. API-функция проверяет сегменты и кодирует каждый отдельно для исходящего запроса. Некорректные query-параметры нормализуются; при смене лимита страница сбрасывается на первую.

## Получение списка

1. `usePostsPagination` читает нормализованные `page` и `limit`.
2. Эти значения входят в ключ TanStack Query.
3. `getPosts` запрашивает `/guardian-api/search` с `page`, `page-size`, `order-by=newest` и `show-fields=byline,trailText,thumbnail`.
4. Zod проверяет `response.results`, `response.total` и поля материалов. HTML-анонс преобразуется в текст в инертном template и отображается через React как текст.
5. Возвращаемые данные содержат `posts`, `totalCount`, `page` и `limit`. Последние два поля обозначают именно отображаемую страницу.

`keepPreviousData` сохраняет прежний список до ответа на новый запрос. Ссылки возврата карточек и подпись пагинации используют параметры этих данных, поэтому не приписывают старые статьи новой странице. Кнопки пагинации отключены на время запроса.

## Детали и ошибки

Деталь запрашивает `response.content` с `show-fields=byline,bodyText,thumbnail`. Полный текст загружается при открытии статьи; в списке используется короткий анонс. Текст не интерпретируется как HTML.

Без данных показываются начальная загрузка, ошибка или 404. При ошибке фонового обновления кешированный контент остаётся на экране вместе с компактным уведомлением и повтором запроса. Для пустой или недоступной страницы списка предусмотрен возврат на первую.

Сетевые ошибки и ошибки сервера автоматически повторяются один раз. Ошибки контракта и HTTP 4xx автоматически не повторяются; для ограничения квоты и отсутствия доступа есть отдельные сообщения.

## Ключ API и production

В разработке и preview Vite читает `GUARDIAN_API_KEY` на серверной стороне. Браузер отправляет same-origin запросы к `/guardian-api`.

Production использует multi-stage Docker-образ: Node.js создаёт статические файлы, Nginx раздаёт их и проксирует API. Entry-point проверяет runtime key до подстановки в конфигурацию. Ключ не передаётся как build argument.

Nginx проверяет TLS-сертификат Guardian и формирует upstream query из разрешённых параметров. Клиентские Authorization и Cookie не передаются. Один ключ обслуживает всех посетителей, поэтому лимит в один запрос в секунду общий для контейнера; очередь допускает пять отложенных запросов, затем возвращает `429`. При нескольких контейнерах с одним ключом потребуется общее ограничение выше уровня отдельных экземпляров. Суточная квота этим механизмом не контролируется.

HTML не кешируется, хешированные ассеты получают длительный immutable cache. Для прямых клиентских маршрутов возвращается `index.html`. Healthcheck проверяет доступность Nginx, а не состояние внешнего Guardian API.

Compose публикует порт на `127.0.0.1:8080`. При размещении на сервере HTTPS обеспечивает внешний reverse proxy.

## Проверяемость и ограничения

MSW проверяет поведение компонентов с контролируемыми ответами, Playwright — сценарии браузера, production smoke — настоящий Nginx с изолированным HTTPS upstream и тестовым сертификатом. Подробности — в [разработке](development.md).

SSR, CRUD, собственная база, авторизация и автоматический деплой не входят в объём задания. [Диаграммы](diagrams/README.md) дополняют описание потоков и логической модели; ERD не означает наличие собственной базы.
