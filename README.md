# Лента новостей The Guardian

Одностраничное приложение показывает свежие новости из Guardian Content API, позволяет менять размер страницы, переходить между страницами списка и открывать полный текст новости по прямой ссылке. Репозиторий подготовлен как проверяемое тестовое задание: приложение запускается локально через npm или в Docker, а основные пользовательские сценарии покрываются автоматическими тестами.

## Возможности

- список новостей с состояниями загрузки, ошибки и отсутствия данных;
- заголовок, раздел, дата, автор, текст и иллюстрация новости;
- выбор количества новостей на странице;
- собственная пагинация, синхронизированная с параметрами URL;
- переход на страницу выбранной новости;
- прямые ссылки на список `/posts?page=1&limit=10` и новость `/posts/:postId`;
- проверка ответов API до передачи данных интерфейсу;
- адаптивный интерфейс и доступные элементы управления.

## Стек

- React 19 и TypeScript;
- Vite;
- React Router;
- TanStack Query для серверного состояния и кеша;
- Zod для проверки данных на границе API;
- Vitest, Testing Library и MSW для модульных и интеграционных тестов;
- Playwright для end-to-end сценариев;
- Nginx в multi-stage Docker-образе.

## Быстрый запуск через npm

Нужны Node.js 22.13 или новее и npm.

```bash
npm ci
cp .env.example .env
npm run dev
```

В PowerShell вместо `copy` можно выполнить:

```powershell
Copy-Item .env.example .env
```

Vite выведет локальный адрес приложения в терминал. Укажите выданный Guardian API key в локальном `.env`:

```dotenv
GUARDIAN_API_KEY=replace-with-your-guardian-api-key
```

Ключ читает только Node-процесс Vite. Браузер обращается к same-origin маршруту `/guardian-api`, а dev- и preview-прокси добавляют ключ к исходящему запросу. Переменная не имеет префикса `VITE_` и не встраивается в клиентскую сборку. После изменения ключа перезапустите dev- или preview-сервер.

## Запуск в Docker

Нужен запущенный Docker с поддержкой Compose.

```bash
docker compose up --build -d
```

Приложение будет доступно по адресу [http://localhost:8080](http://localhost:8080). Compose проверяет состояние контейнера через healthcheck.

Остановить окружение:

```bash
docker compose down
```

Compose читает `GUARDIAN_API_KEY` из локального `.env` и передаёт его только запущенному Nginx-контейнеру. Образ собирается в два этапа: Node.js 22 Alpine создаёт статические файлы без секрета, затем Nginx Alpine раздаёт их, проксирует `/guardian-api` к Guardian Content API и возвращает `index.html` для клиентских маршрутов React Router.

## Непрерывная интеграция

Workflow `.github/workflows/ci.yml` разделяет быстрый сигнал для каждого коммита и обязательные проверки pull request:

- при каждом `push` ESLint запускается как быстрый неблокирующий сигнал и оставляет предупреждение в GitHub Summary при ошибках;
- push в `master` или `develop`, а также каждый pull request в `master`, параллельно запускает unit- и интеграционные тесты Vitest с покрытием, end-to-end тесты Playwright и проверку готовности production-образа;
- `PR gate` завершается успешно только после всех трёх блокирующих jobs; этот статус нужно добавить в required status checks правила защиты ветки `master`;
- тот же полный набор можно запустить вручную через `workflow_dispatch` перед релизом.

Production-проверка контролирует форматирование, типы и ESLint, аудит высоких/критических уязвимостей runtime-зависимостей, отсутствие runtime-секрета в клиентском bundle, сборку Docker-образа, подстановку proxy-конфигурации, health endpoint, SPA fallback прямого Guardian-маршрута и HTTP security headers для HTML и ассетов. Отчёты покрытия и Playwright сохраняются в artifacts на 7 дней.

## Архитектура

Состояние текущей страницы и лимита хранится в query-параметрах URL. Компоненты страниц читают эти параметры, API-слой формирует запрос к `/guardian-api/search`, Zod проверяет оболочку `response` и данные новости, а TanStack Query управляет загрузкой, кешем и повторными запросами. Маршрут деталей получает строковый Guardian ID из URL и запрашивает `response.content`.

Production-сборка остаётся статическим SPA, но Nginx служит узким API-прокси, чтобы секрет не передавался в браузер. Собственное хранение и серверная бизнес-логика в задании отсутствуют. Границы модулей и поток данных описаны в [docs/architecture.md](docs/architecture.md).

## Публикация

Для публикации к локальному репозиторию можно привязать пустой репозиторий GitHub и отправить проверенную ветку:

```bash
git remote add origin https://github.com/<account>/<repository>.git
git push -u origin master
```

Не добавляйте токены, `.env` и другие секреты в Git. Для развёртывания используйте Docker-образ на хосте с HTTPS и передавайте `GUARDIAN_API_KEY` только как runtime-переменную. Обычная раздача файлов без API proxy и SPA fallback нарушит загрузку новостей и прямое открытие `/posts/...`; конфигурация Nginx в репозитории учитывает оба случая.

## Ограничения Guardian Content API

Приложение зависит от доступности Guardian Content API, действующего ключа и лимитов выбранного API-плана. Не у каждого материала обязательно присутствуют автор, текст или иллюстрация, поэтому интерфейс допускает отсутствие полей `fields` и показывает безопасные fallback-состояния. Текущая реализация использует только чтение новостей.
