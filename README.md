# Список постов

Одностраничное приложение показывает публикации из открытого API, позволяет менять размер страницы, переходить между страницами списка и открывать отдельный пост по прямой ссылке. Репозиторий подготовлен как проверяемое тестовое задание: приложение запускается локально через npm или в Docker, а основные пользовательские сценарии покрываются автоматическими тестами.

## Возможности

- список постов с состояниями загрузки, ошибки и отсутствия данных;
- выбор количества постов на странице;
- собственная пагинация, синхронизированная с параметрами URL;
- переход на страницу выбранного поста;
- прямые ссылки на список `/posts?page=1&limit=10` и пост `/posts/:postId`;
- проверка ответов API до передачи данных интерфейсу;
- адаптивный интерфейс и доступные элементы управления.

## Стек

- React 19 и TypeScript;
- Vite;
- React Router;
- TanStack Query для серверного состояния и кеша;
- Zod для проверки данных на границе API;
- Vitest, Testing Library и MSW для модульных и интеграционных тестов;
- Playwright для end-to-end сценариев;
- Nginx в multi-stage Docker-образе.

## Быстрый запуск через npm

Нужны Node.js 22 и npm.

```bash
npm ci
cp .env.example .env
npm run dev
```

В PowerShell вместо `copy` можно выполнить:

```powershell
Copy-Item .env.example .env
```

Vite выведет локальный адрес приложения в терминал. По умолчанию API задаётся в `.env.example`:

```dotenv
VITE_API_URL=https://jsonplaceholder.typicode.com
```

Значение должно быть базовым URL без `/posts` в конце. Переменные Vite попадают в клиентскую сборку и не подходят для секретов. После изменения `VITE_API_URL` перезапустите dev-сервер, а production-образ соберите заново.

## Запуск в Docker

Нужен запущенный Docker с поддержкой Compose.

```bash
docker compose up --build -d
```

Приложение будет доступно по адресу [http://localhost:8080](http://localhost:8080). Compose проверяет состояние контейнера через healthcheck.

Остановить окружение:

```bash
docker compose down
```

Образ собирается в два этапа: Node.js 22 Alpine создаёт статические файлы, затем Nginx Alpine раздаёт их и возвращает `index.html` для клиентских маршрутов React Router. Отдельные backend и база данных этому заданию не нужны: браузер обращается к открытому API напрямую.

## Архитектура

Состояние текущей страницы и лимита хранится в query-параметрах URL. Компоненты страниц читают эти параметры, API-слой формирует запрос к `/posts`, Zod проверяет ответ, а TanStack Query управляет загрузкой, кешем и повторными запросами. Маршрут деталей получает `postId` из URL и запрашивает один пост.

Production-сборка остаётся статическим SPA. Это уменьшает объём инфраструктуры и соответствует источнику данных: собственное хранение и серверная бизнес-логика в задании отсутствуют. Границы модулей и поток данных описаны в [docs/architecture.md](docs/architecture.md).

## Публикация

Для публикации к локальному репозиторию можно привязать пустой репозиторий GitHub и отправить проверенную ветку:

```bash
git remote add origin https://github.com/<account>/<repository>.git
git push -u origin master
```

Не добавляйте токены, `.env` и другие секреты в Git. Для развёртывания используйте Docker-образ на хосте с HTTPS. Публичный адрес API должен поддерживать HTTPS и CORS для домена приложения. Обычная раздача файлов без SPA fallback нарушит прямое открытие `/posts/...`; конфигурация Nginx в репозитории этот случай учитывает.

## Ограничения JSONPlaceholder

JSONPlaceholder предназначен для демонстраций и тестов, а не для production-нагрузки. Набор данных ограничен и может не отражать поведение реального backend. Сервис не предоставляет прикладную авторизацию, пользовательские данные или гарантии доступности. Операции изменения данных, если их добавить позднее, нельзя считать постоянным хранением. Текущая реализация использует только чтение постов.
